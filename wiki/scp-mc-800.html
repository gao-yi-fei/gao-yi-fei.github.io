项目编号：SCP-MC-800

项目等级：Safe

特护收容措施：SCP-MC-800被收容于一个小型箱子，并已重命名为“SCP-MC-800”。有计算或实验需要的人员可以申请站点主管出借项目。

描述：SCP-MC-800是一份异常的书与笔。最初发现时的名称为“N IDE”，并且内含一段“样例代码”。虽然该段代码已被遗忘，但经过相关人员的回忆和测试，该代码采用的语言的表现形式和语言特性已被知晓。此编程语言被基金会命名为“N”。

在项目中输入一个N表达式，然后合上项目，项目就会进入一个被推测为“计算”的状态，该状态的持续时间与人工模拟执行该代码（如果可以）的时间成正比。在此状态中，项目依然可以被打开，但如果此时修改内容，“计算”将重新开始。“计算”结束后打开项目，将发现内容已被替换为计算结果（计算表达式而得到的文本值或错误信息）。

以下为N的语法和语言特性，按照符号优先级从高到低排序。

符号功能
括号 ()调整符号结合顺序。
函数记号 '表达一个单参函数。记号左侧为参数名，右侧为函数值。例如 x'x 是一个将参数直接作为计算结果的函数。该符号为右结合，例如 x'y'x 等同于 x'(y'x)。
调用记号 空格表达一次函数的调用。一个函数和一个值以空格隔开，后者为参数。例如 x'x y 表示当参数为 y 时，函数 x'x 的函数值，即为 y。该符号为左结合，例如 f x y 等同于 (f x) y。
连接记号 空格表达两段文本的连接。若两个文本值以空格隔开，则表示前者末尾连接了后者。例如 "Ha" "ha!" 的值为 "Haha!"。该符号的优先级、结合顺序，同调用记号。
引号 ""表达一段文本。例如 "SCP-MC-800" 是内容为 “SCP-MC-800” 的文本值。
空“空”是这样一种“值”，它保证永远不会参与计算。这是项目最为异常之处，似乎项目有预测后续计算过程的能力。当两个括号或平行记号中间没有值时，可以表示“空”。例如 () 或 (|)。
平行记号 |表达一次非确定性计算。该记号前后的两个值都有可能作为计算结果，除非在那种可能性里，“空”必将参与计算。例如 x | y | z 的值为x、y或z，而 x | () y | z 的值为x或z，因为“空”保证不会参与计算。该符号无所谓左结合或右结合。
赋值记号 :=表达一次对全局变量的设置。记号左侧为变量名，右侧为要设置的值。整个赋值表达式的值总是空文本 ""，但会给相应全局变量以设置的值。例如，计算 1 := "1" 后，可以在后续输入的表达式中用 1 来指示 "1"。该符号只能出现在整个表达式的最外层。

备注：我采用的策略是用函数定义数据结构。以上定义了逻辑类型数据的所有基本操作。虽然N语言的函数只接受一个参数，但是若函数被调用后返回一个函数，就可以接受“第二个”参数了。那么—— true 是这样一个函数，它接受两个参数，并直接以第一个为计算结果。false 则以第二个。这具体如何运作？以 bool->str 这个文本转换函数为例。可以推测项目是这样计算 bool->str true 的：



bool->str true

= b'((b "true") "false") x'(y'x)

= (x'(y'x) "true") "false"

= y'"true" "false"

= "true"

如果给予参数 false，那么同理可以得到 "false"。



> 0 := case0'case1+'case0



> 1+ := n'case0'case1+'(case1+ n)

备注：现在来到了更高级的数据结构：自然数。同逻辑值一样，自然数也有两种：零、其他自然数加一。对于零，可以直接仿照上面的 true 来定义。但对于“自然数加一”，就要考虑是哪个自然数了。1+ 是一个自然数的“构造函数”，虽然看起来接受三个参数，但是

1+ n

才是一个真正的自然数，即我们说的 n + 1。在以上体系中写作 case0'case1+'(case1+ n) ——那么，它也就与上面的 false 类似，接受两个参数，并且只用到第二个参数。但与彼不同，这里要求第二个参数也是一个函数，它接受一个比 n + 1 小了 1 的自然数 n，来传达调用方：既然这个自然数不是零，那么它的前一个数是什么？

**备注**：非确定性树上查找算法意料之中地通过了测试，符合“能得到任意正确答案”的预想。现在我已经完全理解了文档中对各种语言特性的描述，也就是说，表象已经通晓——而我接下来要思索的是原理。项目是如何预知“空”的？“空”意味着什么？

[[/collapsible]]

------

> ++ **提议880-1**

> +++ **Dr. X█ 致 O5-MC 议会。**

> 

> 我要求立即集中大量研究人员以开展对SCP-MC-800的精密研究；或者干脆直接将其无效化，投进熔岩之类的——我们还没试过呢。它就算安稳地搁在箱子里，也足以使人胆寒。

> 

> SCP-MC-800并非字面的“Safe”。相反，它有潜力造成ZK级事件。诸君应该已经玩味了我那尽力写得深入浅出但依然晦涩不堪的黑箱测试记录。想过吗？项目如何预知“空”？“空”意味着什么？

> 

> 我的看法：每当计算一道 | ，平行世界诞生；每当计算一个“空”，平行世界湮灭。想想——“非确定性计算”，人们梦寐以求的能力！算力不足者的救世主！——不就能被看作这样的一个暴君吗？

> 

> 当我写下 map-find map-for-testing 2 时，命运将我们带向何方？九个 nil，五个 0，而只有两个 2。还不算自然数的相等判定算法！这是疯狂的漂流，我们将撞向十六个地方，只有两个地方是生门。存者且偷生，死者长已矣！毁灭的世界不会知道自己的毁灭，而幸存的我们还在欢庆暴君的神力。

> 

> 也许将来有一天，某个好奇的研究员在项目里写下了短短的两个字符“()”，然后轻合书页，等待着那个不可能的计算结果。因为项目必须要给出结果，或陷入死递归，而后者必不存在于那两个字符中，那么他令世界的存在陷于不可能。命运。

> 

> 愿认真考虑。
